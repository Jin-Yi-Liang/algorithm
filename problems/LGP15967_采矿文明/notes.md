# 采矿文明 - 思维框架笔记

## 第一步：看清楚"限制"的本质

拿到题目先问自己：**哪些东西是固定的，哪些是我能选择的？**

这道题里：
- **固定的**：走到第 $j$ 个矿井，交通费就固定了，没得选
- **能选择的**：在哪些矿井采矿、采多少

发现"交通费固定"之后，问题就少了一个变量。

## 第二步：尝试"固定一个变量"

题目让你同时决定"走到哪里"和"选哪些矿"，感觉很复杂。

这时候一个常见技巧是：**把其中一个决策固定，看另一个怎么做最优。**

> 假设我已经决定走到第 $j$ 号矿井，剩下的问题怎么解？

固定终点之后，剩下的钱是确定的，问题变成：
**"有固定的预算，从有限的矿里选K个，怎么采最多？"**

这个子问题一眼就能看出来——**贪心，选最大的K个**。

## 第三步：子问题简单了，就枚举那个"固定的变量"

既然固定终点后很好做，那就**枚举所有可能的终点**，每个都算一次答案，取最大值。

这就是"枚举终点"的来源。

## 第四步：发现枚举有重复计算，想办法加速

朴素做法：枚举每个 $j$，都重新找前 $j$ 个矿里最大的 $K$ 个。

但这样每次都要重新排序，太慢。

这时候问自己：**从 $j$ 到 $j+1$，变化了什么？**

> 只是多了一个新矿井 $A[j+1]$，其他都没变。

那就只需要**在上一步的结果上做微小更新**，而不是从头重算。这就引出了用堆来维护。

## 总结成一套思路框架

```
1. 读完题，找出哪些是"固定的"，哪些是"要决策的"
        ↓
2. 决策太多、太复杂？
   → 尝试固定其中一个，看剩下的是否变简单
        ↓
3. 子问题变简单了？
   → 枚举那个被固定的变量，对每种情况求解
        ↓
4. 枚举太慢？
   → 观察相邻两次枚举的"差异"，用数据结构维护增量更新
```

## 更重要的一点

这种思路不是天生就会的，是**做题做多了之后形成的直觉**。

比如"固定一个变量"这个技巧，它在很多题里出现：
- 固定右端点，维护左端点的最优值（滑动窗口）
- 固定某一维，另一维排序后贪心
- 固定终点，反推最优路径

**每次做完一道题，不要只记答案，要记"我在哪一步想到了什么"**，慢慢就能形成自己的直觉。

## 交通费的计算

题目给的 $C = [2, 1]$ 含义是：

```
矿井1 ---(花2元)--> 矿井2 ---(花1元)--> 矿井3
```

**到达第 $j$ 号矿井**，只需要付"路上经过的路段"的费用：

| 终点 $j$ | 经过的路段 | 交通费 |
|---|---|---|
| $j=1$ | 没有移动 | $0$ |
| $j=2$ | 矿井1→矿井2 | $C_1 = 2$ |
| $j=3$ | 矿井1→矿井2→矿井3 | $C_1 + C_2 = 2+1 = 3$ |

**所以 j=2 时**：

$$\text{budget} = M - \text{交通费} = 10 - 2 = 8$$

简单记：**走了几段路，就付几段的钱**，$j=2$ 只走了一段（1→2），所以只付 $C_1=2$。
