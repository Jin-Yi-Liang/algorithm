# 数列变非递减 - 题解笔记

## 核心思想：从后往前贪心

### 为什么从后往前处理是最优的？

1. **操作只能让数字变小**（一位数除外，但一位数操作后不变）

2. **非递减要求**：最终数组需要满足 `a1 ≤ a2 ≤ ... ≤ an`

3. **从后往前**：
   - 最后一个数 `an` 没有后面的约束，保持原样（操作只会让它变小，增加前面数满足条件的难度，所以不操作）
   - 然后处理 `an-1`，它必须 `≤ an`。如果 `an-1 ≤ an`，不用操作；否则必须将它变小（操作若干次），直到 `≤ an`
   - 由于只能变小，所以每个数只需要考虑它右边已确定的最终值，贪心选择最少的操作次数（能不变就不变，必须变时变到刚好满足条件或再变一次）

4. **从前往后不可行**：
   - 如果从前往后，假设处理到 `ai`，它必须 `≤ ai+1`，但 `ai+1` 后面还可能被操作变小
   - 如果 `ai > ai+1`，我们无法让 `ai+1` 变大（只能变小），只能让 `ai` 变小。但 `ai` 变小后，可能又无法满足它与 `ai-1` 的关系，导致需要回溯
   - 而且，为了让 `ai+1` 变大，我们可能会错误地操作它（但操作只会让它更小，无法满足要求），所以从前往后处理会陷入局部最优困境，无法保证全局最少操作次数

### 贪心正确性证明

由于操作只能让数字单调递减，且每个数只受其右边数的约束（不受左边影响），
因此从右往左的决策是**无后效性**的——当前决策不会影响后续（已经处理过的右边的数）的最优性。

### 关键代码

```cpp
for(int i=n-1;i>0;--i){
    while(num[i-1]>=10 && num[i-1]>num[i]){
        num[i-1]=cal(num[i-1]);
        ++ans;
    }
    if(num[i-1]>num[i]){
        printf("-1\n");
        return;
    }
}
```

- `num[i-1] >= 10`：一位数操作后不变，无需继续
- `num[i-1] > num[i]`：需要操作让它变小
- 最终若仍不满足则输出 -1
