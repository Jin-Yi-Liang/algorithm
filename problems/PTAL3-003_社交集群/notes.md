# PTA L3-003 - 社交集群

## 题目链接
https://pintia.cn/problem-sets/994805046380707840/exam/problems/type/7

## 思路
**并查集（Union-Find）** 求解社交集群。
如果把人和爱好都一股脑塞进同一个并查集里，编号就会冲突（比如 1 号人物和 1 号爱好），逻辑会变得一团糟。

我们来看看如何用一种极其优雅的**“桥梁（Bridge）”思维**，把并查集完美地套用在这道题上。
🌉 核心思维：用“爱好”作为桥梁，只对“人”进行合并

我们的核心目标是把有共同爱好的人合并在一起。因此，我们的并查集只为 1 到 N 个人建立（即 parent[i] 记录的是第 i 个人的老大）。

那么，爱好怎么处理呢？我们引入一个“登记册”数组：hobby[1001]。

    hobby[h] 的含义是：“第一个拥有爱好 h 的人是谁”。

🔄 详细操作步骤

第一步：初始化

    让 1 到 N 个人的老大都指向自己：parent[i] = i。

    准备好 hobby 数组，全部初始化为 0。

第二步：拉帮结派（读入数据并动态合并）
假设我们读到了第 i 个人，他喜欢爱好 h。我们去查一下登记册 hobby[h]：

    如果 hobby[h] == 0：说明这个爱好以前从来没人认领过。那第 i 个人就是开创者！我们记录下来：hobby[h] = i。

    如果 hobby[h] != 0：说明之前已经有一个人（假设叫 k，即 k = hobby[h]）喜欢过这个爱好了！这就意味着 i 和 k 有共同爱好，他们属于同一个社交集群！

        我们立刻执行并查集的合并操作：Union(i, k)，让他们的老大拜把子。

第三步：清点每个集群的人数
所有人的爱好都处理完后，集群也就划分好了。但怎么统计每个集群有多少人呢？

    我们准备一个计数数组 count[N+1]，全设为 0。

    遍历每一个人（i 从 1 到 N），找到他真正的最高首领：root = Find(i)。

    让首领麾下的人数加一：count[root]++。

第四步：排序并输出

    遍历 count 数组，把所有大于 0 的数字提取出来。

    从大到小降序排列。

    先输出一共有几个大于 0 的数字（即集群总数），再依次输出每个集群的人数。

核心思想：**共同爱好 → 同一集合**

- `hobby[h]` 记录爱好 h 当前遇到的第一个人（初始化为 -1）
- 遍历每个人的爱好列表：
  - 如果该爱好还没人有过，记录这个人
  - 如果已有人有过，将这个人与那个人的集合合并
- 最后统计每个集合的大小，降序输出

## 复杂度
- 时间：O(N × K × α(N)) ≈ O(NK)，α 为 Ackermann 函数的反函数（几乎常数）
- 空间：O(N + H)，H=1000 为爱好数量

## 代码要点

```cpp
// 关键数据结构：
int parent[1005];  // 并查集：每个人指向其父节点
int rank[1005];    // 按秩合并的秩
int hobby[1005];   // 每个爱好当前的第一人，-1 表示无人

// 合并逻辑：
if (hobby[tmp] == -1) hobby[tmp] = i;        // 第一次遇到该爱好
else myUnion(parent, rank, n, i, hobby[tmp]); // 与已有该爱好的人合并
```

## 并查集三要素
1. **find**：路径压缩（递归 + 父指针直接指向根）
2. **union**：按秩合并（秩小的挂载到秩大的下面）
3. **路径压缩 + 按秩合并** → 近乎 O(1) 的操作

## 关键点
- `hobby[tmp]` 只需要记录**第一个**拥有该爱好的人
- 集群数量 = 独立集合的数量（parent[i] == i 且 gronum[i] > 0）
- 输出按人数**非增序**（降序）
