核心的突破口在于“能被 4 整除的数有什么特点”。

根据数学常识，一个数能不能被 4 整除，**只取决于它的最后两位数**。如果最后两位数能被 4 整除，整个数就能被 4 整除。在这个题里，字符串只包含 `1, 2, 3, 4` 这四个数字，这就让情况变得非常简单了。

## 第一步：干掉所有的 `4`

首先，数字 `4` 本身就能被 4 整除（$4 \div 4 = 1$）。

这意味着：**原字符串里只要出现任何一个 `4`，它自己就能独立组成一个被 4 整除的子序列。**

所以没有任何悬念，**所有的 `4` 必须全部删掉**。

> **结论 1：** 统计字符串里有几个 `4`，直接加到答案里，接下来的分析完全不需要再考虑 `4`。

## 第二步：找出剩下的冲突组合

去掉所有的 `4` 之后，字符串里只剩下 `1, 2, 3` 了。那么，由 `1, 2, 3` 组成的两位数中，有哪些能被 4 整除呢？

我们穷举一下：

- 以 1 结尾：11, 21, 31（都不能）
- 以 3 结尾：13, 23, 33（都不能）
- 以 2 结尾：**12**（可以！$12 \div 4 = 3$）、22（不能）、**32**（可以！$32 \div 4 = 8$）

发现了没？唯一的违规组合就是 **`1` 后面接了 `2`**（形成 12），或者 **`3` 后面接了 `2`**（形成 32）。

只要你的字符串里存在一个 `1` 或 `3`，并且它的后面某个位置存在一个 `2`，那你就能把它们挑出来组成 `12` 或 `32`，这个字符串就不美观了。

> **结论 2：** 为了不让 `1` 或 `3` 出现在 `2` 的前面，最终合法的字符串必须满足：**所有的 `2` 都必须排在所有的 `1` 和 `3` 之前。**

也就是说，最终留下来的完美字符串，形式一定长这样：

`222...222` 后面紧跟 `1311333...`（前面全是 2，后面全是 1 和 3 的混合）。

## 第三步：寻找最佳“分割点”（核心算法）

既然合法的结构是“左边全是 2，右边全是 1 和 3”，我们就可以在字符串中画一条**分割线**。

假设我们在某个位置画一条线：

- 这条线**左边**的所有 `1` 和 `3` 都要被删掉（只留下 `2`）。
- 这条线**右边**的所有 `2` 都要被删掉（只留下 `1` 和 `3`）。

我们要做的，就是用一重循环，把这条线从字符串的最左端一直挪到最右端，看看挪到哪个位置时，**“左边的 1,3 个数 + 右边的 2 个数”** 的总和最小。

这里其实有点像滑动窗口一样，只不过本题滑动的是一个分割线，看线左边又没有1或者3,有的话就需要删掉。看线段右边又没有2,有的话就需要删掉

---

### 拿一个具体的例子来走一遍：

假设去掉了 `4` 之后，剩下的字符串是：`1 3 2 2`

我们总共拥有：`total_2 = 2` 个（所有的 2）。

我们开始从左到右枚举分割线的位置：

1. **分割线在最左边（`| 1 3 2 2`）：**
   - 左边：什么都没有（删掉 0 个 1或3）
   - 右边：有 2 个 `2`（必须全部删掉）
   - 代价 = $0 + 2 = 2$
2. **分割线往右移一个（`1 | 3 2 2`）：**
   - 左边：有 1 个 `1`（必须删掉）
   - 右边：有 2 个 `2`（必须全部删掉）
   - 代价 = $1 + 2 = 3$
3. **分割线再往右移（`1 3 | 2 2`）：**
   - 左边：有 1 个 `1` 和 1 个 `3`（共 2 个，必须删掉）
   - 右边：有 2 个 `2`（必须全部删掉）
   - 代价 = $2 + 2 = 4$
4. **分割线跨过第一个 2（`1 3 2 | 2`）：**
   - 左边：有 2 个（`1` 和 `3`，必须删）
   - 右边：剩下 1 个 `2`（必须删）
   - 代价 = $2 + 1 = 3$
5. **分割线移到最右边（`1 3 2 2 |`）：**
   - 左边：有 2 个（`1` 和 `3`，必须删）
   - 右边：剩下 0 个 `2`
   - 代价 = $2 + 0 = 2$

在这个例子中，最小的调整代价是 `2`（对应第 1 种或第 5 种方案）。比如方案 5，删掉左边的 `1` 和 `3`，剩下 `2 2`，它就是美观的。

```c++
string str; //存储需要遍历的数字字符串
ans+=total_2;  
int i=0,tmp_ans=ans;  //i是遍历的索引下标、tmp_ans是遍历过程中的需要移动的总数，ans是tmp_ans的最小值，也就是答案。
//tmp_ans被初始化为2的数量，也就是   | 1 3 2 2   这个状态
while(i<str.size()){
    if(str[i]=='1' || str[i]=='3'){  //如果当前数字要进入分隔线左边，那么看是否是1或者3，如果是就需要删除，tmp_ans++;
        ++tmp_ans;
    }
    else if(str[i]=='2') --tmp_ans;  //如果当前数字要进入分隔线右边，那么看是否是2，如果是就说明这个2不需要删除，tmp_ans--;
    ans=min(ans,tmp_ans);
    ++i;
}
```

---

## 总结你的代码缺了什么

你之前的写法之所以 AC 不了：

1. **陷入了局部纠结**：只要看到 `1` 或 `3` 后面有 `2` 就盲目去删前面的，没有从全局“左边全是2，右边全是1和3”的结构去考虑。
2. **重复扫描导致超时**：每次都用 `find` 去后面找 `2`，把 $O(N)$ 的线性问题硬生生做成了 $O(N^2)$。

而用这种**前后缀统计（分割点思维）**，我们只需要在开头数一下总共有多少个 `2`，之后一边遍历一边累加左边的数量、递减右边的数量，就能在 $O(N)$ 时间内优雅地拿到最优解。

---

```c++
#include<bits/stdc++.h>
using namespace std;
#define ll long long

void solve(){
    string str;
    cin>>str;
    int ans=0,total_2=0;
    //delete all '4'
    for(auto cur:str){
        if(cur=='4') ++ans;
        if(cur=='2') ++total_2;
    }
    //to enum the pos of line from 0 to str.size()-1
    //if '1' or '3' is at left of line, it need to be deleted
    //if '2' is at right of line, it need to be deleted
    //ans is the num to deleted
    ans+=total_2;
    int i=0,tmp_ans=ans;
    while(i<str.size()){
        if(str[i]=='1' || str[i]=='3'){
            ++tmp_ans;
        }
        else if(str[i]=='2') --tmp_ans;
        ans=min(ans,tmp_ans);
        ++i;
    }
    printf("%d\n",ans);
}

int main(){
    int q;
    cin>>q;
    while(q--) solve();
    return 0;
}
```
